# Remaining Surfaces Audit Report — Aranya Ceylon — 2026-09-03

Scope: the customer-facing surfaces not covered by the two prior audit cycles —
product catalog + search, public blog/journal, account/wishlist/order-tracking,
and gift sets + recipes (including their admin CRUD, which had never been
reviewed — the earlier admin-console audit only covered orders/products/blog/
dashboard). Four parallel focused passes, each independently verified against
the actual code (not survey-level).

Status legend: `pending` | `in-progress` | `done` | `skipped (reason)`

**Headline:** no auth/IDOR/payment-integrity holes were found on any of the
four surfaces — the ownership-check discipline from the earlier audits (filter
by `userId` in the query itself, not after fetch) holds up consistently in
wishlist, orders, and addresses. What this pass found instead is a different
class of problem: **real backend features whose frontend never actually
consumes them**, and **two features that were scaffolded but never fully wired
end-to-end** (gift sets, recipe shopping) — both of which mean money can
silently not reach the cart/checkout it visually appears to reach. Two
findings (#2, #3) are genuinely serious: admin-edited gift-set prices don't
affect what customers are charged, and admin-created gift sets are never
actually purchasable.

## Wave 1 fix notes

- **#1:** `headlinePrice()` no longer falls back to the wrong-currency variant pool when no matching-currency variant exists — it now falls straight to the existing "no price" sentinel (`"Rs 0"` / `"$0.00"`, the same one the function already used for the "no variants at all" case one line below), instead of mislabeling a real cross-currency number. No consumer changes needed — same `string` return type, same sentinel convention already established in the function.
- **#2 / #3:** These are the same root cause, fixed together in `gift.admin.controller.ts`. `createGift` now creates the backing `Product` + one `Variant` per market inside a transaction (mirroring `seed-gifts.ts`'s exact conventions: slug `gift-<giftSlug>`, SKU `GIFT-<slug>-{LKR,USD}`, DRAFT/catalog-hidden status, stock 999), so an admin-created gift set is purchasable immediately, not only ones seeded via the one-off script. `updateGift` now syncs the backing variants' price and weight on every edit, looked up by the *pre-update* slug so a slug rename doesn't orphan the backing product (renames it instead). Both changes are additive/backward-compatible: `updateGift`'s sync is a no-op (not an error) for any gift set that predates this fix and has no backing product yet. Added `gift.admin.controller.test.ts` (new file, 7 tests) covering backing-product creation, category reuse, price sync, weight recompute on contents change, slug-rename handling, and the graceful no-backing-product no-op.
- **#4:** `recipes/[slug]/page.tsx` now resolves `recipe.spices` against a live `listProducts({ limit: 100 })` fetch (server-side, same page-load cost class as the journal/catalog pages' own live fetches) before falling back to the demo catalog — only when the live fetch fails or nothing resolves. `SpiceShop` no longer calls `recipeSpices()` itself; it receives the already-resolved list as a prop, so cart lines added from a recipe page now carry real `productId`/`variantId` and actually reach checkout.
- **Verification:** cannot run `npx tsc --noEmit` / `npx vitest run` / `prisma migrate deploy` from this worktree (no `node_modules`, no DB access). No new migration in this wave — #2/#3 use only existing schema.

## Wave 2 fix notes

- **#5:** Added a `toAccountAddress()` mapper reading `order.shippingAddress`'s snapshot fields directly onto `AccountOrder.shippingAddress`; `AccountDashboard.tsx`'s `addr` computation now prefers it over the demo address-book lookup (`shipTo`), which only ever matched demo orders anyway.

- **#8:** The article page now fetches a small live-post window (`listBlog({ limit: 12 })`) and computes related posts as same-category-first, falling back to the static demo set only when the live fetch fails or returns nothing.
- **#9:** Catalog and search price sorts now read `p.lkr`/`p.usd` based on the active market instead of always `p.usd`.
- **#10:** Per explicit user decision, built real backend support: added `Product.flavour` (`String[] @default([])`, migration `20260903130000_add_product_flavour`), wired it through `createProductSchema`/`updateProductSchema`/`product.service.ts`, and added a flavour tag-toggle control to the admin product editor (reusing `CATALOG_FACETS.flavour` as the single-sourced vocabulary). **Needs `prisma migrate deploy` before merging.**
- **#11:** Per explicit user decision, implemented real component-stock decrementing rather than documenting it as unlimited. Found a workable approach without waiting for Wave 1's gift-linking rework: `GiftSet.jar` already tells us the per-component portion size seed-gifts.ts packs into each box (e.g. "50g"), so `confirmOrderPaid` now resolves each `GiftSet.contents` name → a real `Product` (exact name match) → the `Variant` matching that jar weight + the order's market, and decrements it by the box quantity purchased, inside the same atomic transaction as the box's own stock decrement. An unresolvable component (no matching product/variant, or insufficient stock) is logged to the order's timeline for manual review — never blocks the order, matching the existing oversold-handling pattern. This is necessarily best-effort (name-based matching, no real FK) since `GiftSet.contents` is a plain string array; a cleaner fix would restructure it to reference real products directly, which is squarely in Wave 1 #2/#3's territory (gift-set/backing-product linkage) if that's ever revisited.
- **#12:** Added Intro/Spices/Ingredients/Method/Tips fields to the admin recipe editor drawer (textarea-based, same `ad-field`/`ad-textarea` styling as every other field in the drawer) and wired them into the save payload for both the live-backend and demo/offline paths. Ingredients (a grouped `{group?, items[]}[]` shape) are represented as one line per item with a `# Group name` line starting a new group — documented inline in the placeholder text.

## What was checked and found clean (not regressions to introduce)

- **IDOR**: every account-scoped endpoint (wishlist, orders, addresses) filters by `userId` in the Prisma query itself; the shared guest/authenticated `/orders/:id` route correctly branches and 403s cross-user access.
- **Admin gift/recipe RBAC**: `requireAuth` + `requireRole('ADMIN','SUPERADMIN')` + `adminLimiter` correctly inherited by all 10 gift/recipe admin endpoints; every admin update/delete does an ownership/existence `findUnique` before mutating.
- **Client-supplied price injection**: `addToCartSchema` accepts only `productId`/`variantId`/`quantity` — no client-controlled price field anywhere in cart/checkout, gift sets included.
- **Blog visibility**: public listing/detail endpoints correctly filter `status: PUBLISHED`; no way to fetch a draft/scheduled post by slug or id.
- **XSS/sanitization**: rich-text article bodies sanitized on every render path; JSON-LD and Next Metadata both properly escape article-derived strings.
- **SQL injection**: both raw product-search queries use parameterized tagged templates.
- **Pagination bypass / ReDoS**: product listing capped via Zod; search-token regex escapes metacharacters first.
- **Public recipes page**: does call the live backend with demo-data fallback only when unreachable (contrary to a stale README note) — admin-published recipes do reach real customers on `/recipes`.
